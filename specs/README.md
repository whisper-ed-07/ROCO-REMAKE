# specs 目录说明

> 2026-11-02 建立。宠物文档统一放在 `pets/`（每宠一份 `.md` 机制文档 + 一份 `.txt` 原文）；本目录保留模板、流程与这份说明。代码与文档不一致时以「玩家裁定 + 原文」为准，而不是以代码为准。

## 文件约定

| 路径 | 作用 | 修改规则 |
|---|---|---|
| `pets/<宠物名>.txt` | 玩家原始文本（逐字） | 只由玩家提供/替换；不要改写措辞 |
| `pets/<宠物名>.md` | 机制文档：设计 + 当前实现 + 已知偏差 | 每次机制改动后同步更新，并在文末「修订记录」留一行 |
| `PET_TEMPLATE.md` / `PET-CREATION-FLOW.md` | 新宠物流程与模板 | 流程变更需玩家确认 |
| `pets/清灵.md` 附录 A | 旧规格与 A1-A11 裁定片段 | 只增不改；完整裁定应迁入 `DECISIONS.md` |
| `pets/_source/<宠物名>.html` | 原文抓取时的 HTML 存档 | 只读；用于核对纯文本是否丢格式/图片 |

## 修复机制时的操作顺序

1. 在机制文档里定位偏差编号（M1、M2…），先确认「设计应该是什么」——需要原文或玩家裁定。
2. 改代码（一个偏差一个 commit，提交信息引用编号，如 `修复 M5: 轻风散魂闪避`）。
3. 更新机制文档：§4 实现描述、§5 状态、文末修订记录。
4. 跑 `node test/static-checks.js` + 16 场矩阵；若断言已固化为 `test/run-tests.js`，一并执行。
