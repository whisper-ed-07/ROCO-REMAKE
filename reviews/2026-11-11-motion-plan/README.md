## 3. 动画规格

以下是首轮实现值，可以在视觉验收后小幅调节；不是已经测得的最佳值。统一用 CSS 变量管理，不在多个函数中散落同一个数字。

| 场景 | 建议效果 | 时长 / 约束 |
| --- | --- | --- |
| 启动页进入菜单 | 启动层淡出，底层菜单直接就位；去掉全屏放大 | 360ms，一次即可 |
| 菜单、选宠、管理、设置之间切换 | 内容淡入并上移 8px 到位；去掉全屏缩放、亮度闪变 | 200ms；第一版不保留整张旧页做退出动画 |
| 首次进入战斗 | 战场轻淡入，宠物可短距离进入 | 200–240ms；不新增倒数、黑屏、等待步骤 |
| 按钮悬停 / 按压 | 边框、背景渐变；按压缩至 0.985 | 120ms；不改变实际点击时机 |
| 选宠 / 装备选择 | 选中边框和底色变化，沿用现有勾选标记 | 140ms；不让整张网格逐张飞入 |
| 技能配置区展开 | 内容淡入、上移 6px | 180ms；装备、排序后的局部更新不重播整个面板 |
| 普通弹窗 / 技能详情 | 遮罩淡入，内容上移 8px、从 0.985 到 1 | 开 180ms / 关 140ms；正文不逐行入场 |
| 换宠面板 | 从当前位置下方 12px 进入，保持水平居中 | 开 180ms / 关 140ms |
| HP / 护盾条 | 从当前显示值平滑到真实值；数值文字立即更新 | 实条 280ms；扣血残影延后 80ms，用 420ms 追平 |
| 受击 / 治疗 | 失血短促横向偏移，治疗沿用漂字；不整屏震动 | 受击 180ms、最大 4px；漂字 700ms |
| 换宠后的新宠 | 只给发生变化的一侧淡入，上移 6px | 180ms；未换的一侧、日志和技能栏不重播入场 |
| 胜负结果 | 遮罩与现有结果内容一次淡入 | 开 220ms / 关 140ms；取消结果图标无限缩放 |

建议变量：`--motion-fast: 120ms`、`--motion-state: 140ms`、`--motion-panel: 180ms`、`--motion-page: 200ms`、`--motion-intro: 360ms`、`--ease-enter: cubic-bezier(.2,.7,.2,1)`。HP、残影及漂字另用有明确含义的变量。退出使用简单 ease-in，不做弹簧或回弹。

环境背景保留现有缓慢色带，降低注意力占用；不增加粒子、扫光或持续闪烁。悬停效果只对支持 hover 的设备启用，键盘焦点轮廓立即可见。

## 4. 实施边界与技术要求

### 4.1 页面切换保持同步

- 移除 `.screen` 的自动入场规则，改为只由 `showScreen` 在目标页面挂载后添加一次入场类。
- 在修改 `gameState.screen` 前记录旧页面。旧、新页面相同视为刷新，不播放页面切换；`renderTeamChoice`、`renderBattle` 的直接调用同样不自动入场。
- 首轮用“同步替换 + 新内容短入场”。不缓存两份可交互页面，不复制含 ID 的整页，不引入路由框架或全局输入锁。
- `showScreen` 返回时目标 DOM 和事件已准备好；动画结束回调只清理表现，不调用开战、保存、出招、计时或再渲染。
- 清理页面外、挂在 body 上的旧弹窗与监听。每次真正导航更新一个仅用于 UI 的版本号，过期清理不得影响新页面。
- 导航后焦点落在新页标题或合理的第一个控件；同页选择与排序保留现有回焦行为。不要因 `animationend` 再次抢焦点。

### 4.2 同页变化与弹窗生命周期

- 选宠首次渲染保持现有入口；切换选择只同步 `.selected`、`aria-pressed`、已选数量和确认按钮 disabled 状态。选择上限仍是 6，只能选至少 1 只再继续。
- 技能配置保留现有保存与排序规则。首次打开配置区可入场，连续装备、卸下、排序只更新必要内容，并保持按钮焦点和滚动位置。第一版不做复杂的排序轨迹动画。
- 为各类弹层复用小型“打开 / 正在关闭 / 已关闭”辅助逻辑。关闭最多执行一次；清理捕获的具体旧节点，不重新按 ID 查询后删除。
- 普通关闭可保留节点完成退出，但其提交按钮应立即失效，避免重复保存。详情关闭期间仍封住焦点，完成后再回到有效触发器；焦点不得落到已销毁页面。
- 同 ID 弹窗重开、跳页、保存后立即刷新页面时，旧窗应立即清理，不等待退出动画，不留下重复 ID 或旧键盘监听。
- 技能详情原有 Esc、背景、关闭按钮、Tab / Shift+Tab 行为全部保留。关闭、快速重开、连续 Esc 均只有一个有效弹窗。
- 换宠确认、换宠取消、逃跑确认及结果返回等业务动作仍按原时点发生。若业务已销毁弹层，允许直接结束退出动画，不能延迟业务来凑完整动画。
- 监听 `transitionend` / `animationend` 时检查事件目标和属性，子节点事件不能提前完成父层；必须提供兜底清理与取消路径。

### 4.3 战斗视觉与结算隔离

- 视觉快照只存在 UI 层，不写进 `BattlePet`、存档或技能对象。按 `battleId + 阵营 + 当前宠物对象身份` 识别，不能仅凭宠物名称或模板 ID（新局可能同名）。
- 初次挂载与新宠入场直接使用真实 HP / 护盾；不要从 100% 播到现值。双方采用相同更新器。
- 失血残影从上次显示值追到最新值；恢复时跟随最新 HP，不保留虚假的失血残影。连续变化覆盖旧视觉任务，无变化的 update 不重新延后残影收敛。
- UI 重建时为未更换的一侧恢复视觉状态，并保留日志的阅读位置；只为身份变化的一侧播放新宠入场。不得额外调用 `renderBattleActions` 来重启动画，因为它会重置计时器。
- `spawnFloatText` 先精确匹配当前双方宠物对象；后台宠物不显示在前台，照常保留已有战斗日志。只在既有实际伤害通知中触发失血反馈，不根据技能类别或描述猜测是否受击。
- 护盾漂字当前同时服务增加和吸收，不能仅凭 `type === 'shield'` 推断它是攻击或治疗。此轮沿用其文字与数值，不增写机制判断。
- 清除 legacy 末尾无条件受击的纯 DOM 代码时，必须保持周围结算、`updateBattleUI`、`checkFaints` 次序不变。禁止顺带重构技能执行。
- `checkFaints` 判定、自动替补、`endBattle` 停表立即生效。第一版不强制播放旧宠倒下再替换，以免拖延真实状态或在多次同步替换时显示过期对象。
- `resolveTurn`、AI 决策、伤害/治疗/PP 数值、20 秒计时、800ms 换宠/受控跳过延时均保持原语义。不要 `await` 动画后再结算，不插入新回合队列。
- 不从同步回合中的最终 HP 差值反推多段攻击记录。需要逐段演出时，另做明确的事件呈现设计。

### 4.4 减少动态效果与性能

- `prefers-reduced-motion: reduce` 下停止背景循环、位移、缩放、抖动和延迟；CSS 同时清零 animation-delay 与 transition-delay。
- JS 也查询该偏好。无动画、元素已脱离 DOM 或偏好在播放中切换时，视觉清理立即完成；不存在 API 时安全降级，保证本地 HTML 和 Node harness 可加载。
- UI 辅助函数的取消、结束、偏好变化监听有统一清理；退出页面或新局开始清除旧视觉任务。不能依赖浏览器一定触发动画结束事件。
- 以 opacity、transform 为主，条形变化允许 width；不持续动画化大面积 blur、filter 或布局尺寸，不在全页面长期设置 will-change。
- 启动、导航、弹窗不串联多个等待。用户操作不因装饰动画被排队；关闭动画期间原弹层只负责拦住穿透点击，不能触发第二次业务动作。

## 6. 验收清单

### 功能与生命周期（可自动化）

1. `showScreen` 返回后目标元素立即存在；快速 menu → team → menu 后只剩最后页面，旧动画结束事件不能跳回旧页。
2. 同页选中/取消只更新选择状态；1–6 只限制、确认按钮状态、焦点保持正确。配置装备与排序保持四槽、原顺序及保存数据。
3. 详情保持 PP 为 0 时可打开、不能误触施放；关闭按钮 / 背景 / Esc 各能退出，Tab 与 Shift+Tab 不离开弹窗。
4. 弹层快速关闭重开、导航时关闭、保存连续点击，只产生一次关闭/提交；旧回调不得移除新窗或夺回焦点。表单输入不因动画重建丢失。
5. 动画结束事件缺失、触发子节点事件、元素提前被删除、reduced-motion 开启及播放中开启，都能完成清理；没有透明遮罩、残留监听或动画锁。
6. 同一宠物连续失血/回血、连续无变化刷新，双方血条和残影最终严格收敛到真实比例；新宠初次显示正确，旧宠的清理不操作新宠。
7. 后台宠物伤害/治疗不漂字到敌方；伤害漂字归属正确；纯变化技能无实际失血时不抖动。
8. 保留倒计时原行为：视觉刷新不得重启或额外暂停 20 秒计时；换宠 800ms 回调与受控跳过保护原样工作；退出后旧回调不影响新局。
9. 自动替补、双方濒死、胜负、逃跑、结果关闭后回看日志路径无额外回合、重复 AI 行动或结果层被旧动画覆盖。
10. 阅读历史日志、切换筛选、折叠回合和换宠时保持合理滚动位置；技能条横向滚动与操作顺序 1→4 不变。
